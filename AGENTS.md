# AGENTS.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Common commands
This is a Vite + React app.

### Install
- `npm ci` (preferred for CI / clean install)
- `npm install` (local dev)

### Run dev server
- `npm run dev`

### Production build
- `npm run build`

### Preview production build
- `npm run preview`

### Lint
- `npm run lint`
- Lint a single file: `npx eslint src/path/to/file.jsx`

### Tests
There is currently no `test` script in `package.json`, and no test runner configuration in the repo.

## High-level architecture
### App bootstrap
- `src/main.jsx` is the entry point. It wires:
  - TanStack Router (`createRouter` + `<RouterProvider />`)
  - `AuthProvider` from `src/context/AuthContext.jsx`
  - global styles from `src/index.css`

### Routing (TanStack Router, file-based)
- Routes live in `src/routes/*.jsx` and use `createFileRoute('/path')`.
- `src/routes/__root.jsx` defines the root layout (Toaster + `<Outlet />` + Router Devtools).
- `src/routeTree.gen.ts` is generated by the TanStack Router Vite plugin (configured in `vite.config.js`).
  - Do not edit `src/routeTree.gen.ts` manually.
  - When adding/removing routes, the generated route tree will update during Vite dev/build.

Route-level pages typically import a feature “view” from `src/modules/*/ui/views/*` and sometimes wrap it in the shared `AppLayout`.

### Feature/module organization
Most business functionality is organized by feature under `src/modules/<feature>/`:
- `services/`: API calls for the feature (usually via the shared Axios client).
- `ui/views/`: route-level screens (containers).
- `ui/components/`: feature-specific components.

Examples of feature modules include `auth`, `dashboard`, `agent`, `manage`, `tracker`, `user-tracking`, etc.

Shared UI is in:
- `src/components/` (not feature-specific; e.g. `components/layout/*` and `components/common/*`).

### API / data access
- `src/services/api.js` exports a preconfigured Axios instance.
  - Base URL + timeouts come from `src/config/environment.js`.
  - Adds `Authorization: Bearer <token>` from `localStorage`.
  - Has a global 401 handler that clears auth storage and redirects to `/login`.
- Feature services under `src/modules/**/services/*` and shared services under `src/services/*` (e.g. `src/services/dropdownService.js`) build on top of the Axios client.

### Auth / session model
- `src/context/AuthContext.jsx` is the primary source of truth for auth state in React.
  - User is stored in `sessionStorage` under `user`.
  - Token (for API auth) is stored in `localStorage` using keys from `src/config/environment.js`.
- Some routes also gate access in `beforeLoad` by checking `sessionStorage.getItem('user')` (see `src/routes/index.jsx`, `src/routes/dashboard.jsx`, `src/routes/agent.jsx`, `src/routes/entry.jsx`).

### Environment configuration
- `src/config/environment.js` centralizes all `import.meta.env` reads (Vite env vars).
  - This is the place to add new `VITE_*` settings.
  - Env vars referenced today:
    - `VITE_API_BASE_URL`
    - `VITE_API_TIMEOUT`
    - `VITE_APP_NAME`
    - `VITE_APP_ENV`
    - `VITE_TOKEN_KEY`, `VITE_USER_KEY`
    - `VITE_MAX_FILE_SIZE`, `VITE_ALLOWED_FILE_TYPES`
    - `VITE_DEVICE_ID_KEY`, `VITE_DEVICE_TYPE`
    - `VITE_DEBUG_MODE`, `VITE_CONSOLE_LOGS`
  - It also exposes `log/logError/logWarn`, enabled via `VITE_CONSOLE_LOGS`.

### Initial route behavior
- `src/routes/index.jsx` always redirects on load:
  - if not logged in → `/login`
  - if logged in and `role_id === 6` → `/agent`
  - otherwise → `/dashboard`

### Styling
- Tailwind CSS is integrated via `@tailwindcss/vite` (see `vite.config.js`).
- Global styles and theme tokens live in `src/index.css`.
